# The marketing site: notes for Claude

**The apps page** (flexarr.io/apps) is built from `site/apps.json`, one entry per platform in the order the page shows them. Fields: `id` (the page anchor); `name`; `icon` (`flexarr`, `apple`, `android`, `home-assistant`); `status` (`available`, `beta`, `coming`, `development`, `planned`); `version` (x.y.z, required unless in development or planned); `requires`; `summary`; an optional `note`; `runsOn` (the server's list of systems); and `links`. The first link is the table's *Get it* button, labelled by its `short`; `"store": "apple"` or `"google"` gives a link the store badge, and external links open in a new tab. After editing, run `make apps` and commit both `site/apps.json` and `site/apps.html`; CI fails otherwise. `scripts/release.sh prepare` writes the server's version into the entry marked `"release": "server"`. Everything else is set by hand when it changes: a store build going live, an Android beta opening, an app moving from planned to in development. Examples: when the Apple TV app is approved, set its `status` to `available`, its `version` to the approved build, drop the review `note`, and put an App Store link first (`"store": "apple"`, `"short": "App Store"`), ahead of the Xcode one. When a beta opens, set `beta` with a version and its public link first. A new icon, status or store badge means editing `scripts/apps/build.mjs`.
